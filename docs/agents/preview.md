# Pull Request и превью

## Локальный порядок работы

- Все изменения сначала вносятся и проверяются только локально.
- До явного одобрения пользователя не выполняйте commit, push и не создавайте или обновляйте Pull Request.
- Одобрение распространяется только на уже показанный пользователю набор изменений.

## Ветки и Pull Request

- Работайте в отдельной ветке с префиксом `codex/`.
- Не отправляйте игровые изменения напрямую в `main`.
- Не объединяйте Pull Request без явного запроса пользователя.
- После push дождитесь успешного workflow `Deploy Pull Request preview`.

## Адрес превью

Каждый Pull Request получает собственный адрес:

```text
https://kiraobezjanka-sudo.github.io/re-choose-game/pr-preview/pr-<номер>/
```

Превью обновляется после новых коммитов и удаляется после закрытия Pull Request.
Перед передачей ссылки откройте опубликованную игру и проверьте загрузку HTML, CSS и JavaScript из вложенного каталога.

## GitHub Pages

- Ветка публикации — `gh-pages`.
- Каталог одного Pull Request не должен менять или удалять каталоги других PR.
- Статическая сборка текущей игры публикуется из `dist/`.
- Слияние Pull Request не выполняется автоматически.
